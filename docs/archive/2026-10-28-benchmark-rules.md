## 第 1 条：摸高测试

首页的「还差 x cm」从「最近一次测试的最好一跳」改成「当天最好 3 跳的均值 ± 误差」。单取最好一跳会把偶然的高跳当成进步。

| 规则 | 默认值 | 理由 |
| --- | --- | --- |
| 一次摸高测试跳几次 | 6 次，每次休息 1 分钟 | 够算均值和波动，又不至于累 |
| 当天摸高 | 最好 3 次的均值；不足 3 次就用全部，并标「次数少」 | 比最好一跳稳，又不被没跳好的几次拖低 |
| 误差 | ± 1.96 × √(读数误差² + 这 3 跳的标准差² ÷ 3)；墙面读数误差取 1 cm，录像估算用校准偏差的波动 | 95% 区间，和 App 里其他指标的±一致 |
| 过线把握 | 均值 − 误差 ≥ 扣篮线 =「已过线」；扣篮线在误差带里 =「接近，还不确定」；否则 =「还差 x cm」 | 差距只有 2 cm 时，不确定就要说不确定 |
| 历史曲线 | 新数据用均值；旧记录只有单跳的，照样显示但标「单次」 | 数据不丢，口径分得清 |
| 哪种测量算数 | 墙面/篮板刻度为准；只有录像时用校准后的录像估算，并标出来 | 录像估算还没真机验证（第 2 条） |

## 第 4 条：目标日、预测和减量

计划按目标日倒推：离目标日不到 6 周就不再开力量块，最后 10 天自动减量，目标日当天排「扣篮测试日」。

| 规则 | 默认值 | 理由 / 出处 |
| --- | --- | --- |
| 目标日 | 2026-12-01（「12 月前」按字面理解），在「我的」里可改 | 如果你的意思是 12 月底，告诉我就改成 12-31 |
| 过线预测 | 近 6 周每次摸高测试的均值做线性趋势，给出「预计 x 月 y 日过线，范围 …」；少于 4 次或跨度不到 2 周就不预测 | 数据太少时的预测只会误导 |
| 截止前的块 | 离目标日 < 6 周时，诊断即使是力量块也改排转化块，力量每周维持 1–2 次；首页注明「力量还是短板，目标日后再练」 | 力量增长转化到跳高通常要几周以上 |
| 减量 | 目标日前 10 天：总量减 50%，强度和训练次数不变 | Bosquet 2007 荟萃分析：减量 8–14 天、量减 41–60%、强度保持效果最好 |
| 扣篮测试日 | 目标日当天：热身 → 摸高测试 → 扣篮尝试（第 3 条的记录） | 最后用真实结果验收 |

## 第 5 条：跳跃量和膝盖疼痛

跳跃次数从打勾的组自动算，不用手填；疼痛每天最多点两下。规则按疼痛监测模型（Silbernagel 2007）：训练中疼痛不超过 5/10、第二天早上回到原来水平，就可以继续练。

| 规则 | 默认值 |
| --- | --- |
| 跳跃次数 | 打勾的跳跃类动作（反应、转化里带跳的、助跑摸高）组数 × 次数，单腿动作 × 2；测试日的跳也算 |
| 每节参考上限 | 显示 NSCA 的参考：初级 80–100、中级 100–120、高级 120–140 次触地；超过 140 时提醒，不自动改计划 |
| 什么时候问疼 | 练完问「训练中膝盖最疼几分」；第二天打开 App 问「今早膝盖几分」；0 = 不疼，10 = 最疼 |
| 绿色 | 训练中 ≤ 2，早上不比之前高 → 照常 |
| 黄色 | 训练中 3–5，早上回到原来水平 → 照常练，但跳跃量不加 |
| 红色 | 训练中 > 5，或第二天早上比之前高 → 下一节跳跃次数减半，去掉跳深 |
| 停跳 | 连续 2 次红色，或任何一次 ≥ 7 → 暂停跳跃训练，提示找康复或医生看一下；App 不做医疗判断 |
| 和当天状态的关系 | 红色算一个疲劳信号，进入现有的「恢复差」调整 |

## 第 6 条：体重换厘米

体重改成有历史的记录（手填，或从苹果健康快捷指令一起导入），诊断里多显示一行「体重 −1 kg ≈ 摸高 +x cm」。只显示，不改诊断规则。

- 算法：用你自己的力-速度曲线（已有的 Samozino 模型），假设减掉的是脂肪、绝对力量 F0 和最大速度 v0 不变，把体重换成新值重算最高跳高，差值就是换来的厘米。
- 没测过力-速度曲线就不显示这一行，只提示「先测力-速度曲线」。
- 只算减 1–3 kg 的范围，超出就不算；文案写明是估算。
- 深蹲 ÷ 体重改用测 1RM 那天前后 7 天内最近的体重，没有就用档案里的值（现在是一律用档案里的值）。

## 第 7 条：技术指标

先只测、只显示，不进诊断；真机验证过之后再问你要不要加成第四块。

- 最后一步触地时间：用助跑摸高录像的自动标帧，取起跳前最后一次触地到离地。
- 助跑速度：地上放两个标志物，距离先定 3 m，算最后几步的平均速度。
- 两项都和当天摸高放在一起看，逐步积累「什么节奏跳得最高」。
- 需要确认的只有一点：同意先不进诊断。

## 第 9 条：练前 CMJ 和 trackload

练前 CMJ 从「当天最好一跳」改成「当天 3 跳均值」，基线也用均值；疲劳阈值保持现在的「比近期低 5%」不变。出处：Claudino 2017 荟萃分析，平均跳高比最好一跳更能反映疲劳。跳不到 3 次就用全部的均值。

**trackload（已读 [Sam18069272581/trackload](https://github.com/Sam18069272581/trackload) 的 index.html）**：算法是 sRPE 负荷（时长 × RPE）→ EWMA 急性 ATL（λ = 0.25）和慢性 CTL（λ = 0.069）→ ACWR = ATL ÷ CTL，分区 < 0.8 / 0.8–1.3 / 1.3–1.5 / > 1.5。搬进 Jump Attack 的方式：

| 规则 | 默认值 |
| --- | --- |
| 怎么记负荷 | 练完点「整节课 RPE」0–10；时长用训练开始到结束的时间自动算，可改。墙上不加新的手填项 |
| 两条负荷线 | 整体负荷用 sRPE；膝盖负荷用第 5 条的跳跃次数。两条都用 trackload 同一套 EWMA 和 λ |
| ACWR 怎么用 | > 1.5 算一个疲劳信号，和 CMJ、HRV、膝盖疼痛一起进「当天状态」；单独一个信号不自动减量，只提示 |
| 文案 | 不写「高伤病风险」。ACWR 和受伤的关系近年有争议（Impellizzeri 2020），按「准确比功能多重要」只说「这周负荷比你习惯的高 x%」 |
| 冷启动 | 少于 28 天数据时不显示 ACWR，只显示本周比上周（trackload 自己也写了 CTL 要 28 天才可靠）。所以到 12 月 1 日前它主要是开始积累数据 |
| 对称性 | trackload 里单腿跳左右差 > 10% 的提醒，等单腿 CMJ 有左右两侧数据时一起搬 |
